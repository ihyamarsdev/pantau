# 0068. Kerentanan yang Diketahui pada Paket Terpasang (OSV + Arch Security Tracker)

Melanjutkan tahap **Exploit Intelligence** ([ADR 0064](0064-exploit-intelligence-kev-epss.md)): Security Scan ([ADR 0036](0036-agentless-security-scan.md)) hanya melaporkan ID CVE untuk host dnf/yum, sehingga host apt/apk/pacman berstatus "tidak dinilai" pada intelijen KEV/EPSS. Tahap ini menambahkan pemeriksaan **kerentanan yang diketahui pada paket yang benar-benar terpasang** di host tersebut, memakai basis data OSV (`api.osv.dev`) untuk Debian/Ubuntu/Alpine dan Arch Linux Security Tracker (`security.archlinux.org`) untuk pacman.

## Konteks dan Masalah

1. **Cakupan celah.** Ditemuan Security Scan hanya mencakup pembaruan tertunda dari manajer paket (dnf/yum). Host apt, apk, dan pacman tidak pernah memberi ID CVE ke Pantau, sehingga kartu Exploit intelligence menampilkan "tidak dinilai" — bukan "aman", tetapi juga tidak ada daftar CVE yang bisa ditampilkan.
2. **Advisori ada, hanya tidak pernah ditanyakan.** Database Debian Security Tracker, Ubuntu Security Notices, dan Alpine SecDB sudah tersedia di OSV dalam bentuk yang seragam (ID advisori, alias CVE, versi perbaikan). Pelanggan hari ini harus mencari satu per satu di situs vendor, padahal daftar paket terpasang sudah ada di Pantau.
3. **Paket biner bukan paket sumber.** Advisory Debian dan Alpine melacak paket **sumber** (`openssl`, bukan `libssl3`; `nginx`, bukan `nginx-core`). Inventaris paket yang ada hanya menyimpan nama paket biner, sehingga kueri OSV tidak akan pernah cocok tanpa pemetaan sumber.
4. **Pacman bukan ekosistem OSV.** Tidak ada ekosistem `Arch` di OSV; Arch Linux punya tracker sendiri (`issues/all.json`) dengan skema berbeda (`packages[]`, `affected`, `fixed`, `issues[]`, `status`).
5. **Privasi.** Pemeriksaan ini mengirim nama paket, versi, dan rilis OS ke layanan publik. Pantau harus tetap *airgapped-capable* dan tidak boleh mengirim apa pun tanpa persetujuan administrator.

## Keputusan Arsitektur

1. **Inventaris paket mengingat paket sumber.** Tabel `host_packages` mendapat dua kolom aditif (`source`, `source_version`) lewat helper `ALTER TABLE` yang sudah ada; baris lama tetap valid (nilai kosong → jatuh ke `Name`/`Version`). Pemindaian paket mengambil tambahan ini dari sumber aslinya: dpkg `${source:Package}` + `${source:Version}`, apk field `o:` (origin package) dari `/lib/apk/db/installed`, dan pacman nama biasa (tanpa pemetaan sumber). Parser baru `parseApkOutput` dipakai untuk apk; `parseRpmOutput` tetap untuk rpm/pacman.
2. **Paket baru `internal/osv`.** Klien berbicara dengan `POST {base}/v1/querybatch` (maks 1000 kueri per permintaan, dipecah otomatis) lalu `GET {base}/v1/vulns/{id}` untuk detail (severity, ringkasan, versi perbaikan). Detail di-cache di memori 24 jam (batas 5000 entri, batas 2000 detail per permintaan; kelebihan dilaporkan sebagai catatan), konkurensi unduhan dibatasi 8, timeout 30 detik, ukuran respons dibatasi (4 MiB detail, 32 MiB batch, 32 MiB tracker). Tidak ada yang ditulis ke basis data.
3. **Pemetaan ekosistem.** `EcosystemFor(os_info)` memetakan deskripsi OS yang sudah disimpan Pantau ke string ekosistem OSV: `Debian:<major>`, `Ubuntu:<VERSION_ID>` (ekosistem polos dipakai karena merupakan superset `:LTS` — diverifikasi 2026-11-14), `Alpine:v<major.minor>`. Rilis di luar daftar yang ada datanya di OSV (Debian 7–14, Ubuntu 14.04/16.04/18.04/20.04/22.04/24.04/26.04 + rilis interim, Alpine v3.2–v3.24) berstatus **tidak dinilai** dengan alasannya, bukan daftar kosong.
4. **Ekstraksi kerentanan.** Dari satu advisory diambil: ID dan aliasnya, CVE (dari ID/alias/`upstream`), severity (`database_specific.severity`, lalu skor CVSS, lalu label distro), ringkasan, dan **versi perbaikan** dari event `fixed` pada rentang `ECOSYSTEM` yang cocok dengan ekosistem dan nama paket. Advisory tanpa versi perbaikan tetap dilaporkan tetapi dihitung terpisah sebagai `unfixed_count`.
5. **Arch memakai tracker sendiri.** `internal/osv/arch.go` mengunduh `security.archlinux.org/issues/all.json` (cache 24 jam) dan mencocokkan paket terpasang dengan `packages[]`. **Aturan pencocokan sengaja sempit dan jujur:** paket dilaporkan bila versi terpasang **sama persis** dengan versi `affected`, atau bila versi `fixed` ada dan versi terpasang lebih rendah. Perbandingan "lebih rendah" memakai pembanding versi bergaya pacman yang sederhana (numerik bila numerik, alfanumerik lain); `vercmp` pacman asli tidak diimplementasikan, sehingga versi dengan bentuk berbeda **tidak** diklaim terdampak. Status `Not affected` diabaikan.
6. **Opt-in dan terpisah dari KEV/EPSS.** Pengaturan `osv_enabled` ("1", default mati) di Settings → General. Berbeda dari `vuln_intel_enabled`: fitur ini mengirim nama paket dan versi ke luar, sedangkan KEV/EPSS hanya mengirim ID CVE. Selama mati, tidak ada permintaan keluar sama sekali.
7. **API.** `GET /api/hosts/{id}/security/vulns` (dispatch dari `handleHostSecurity`) menjawab `{enabled:false}` saat mati. Saat aktif: `{enabled:true, status:"assessed"|"not_assessed", source:"osv"|"arch", ecosystem, checked_packages, scanned_at, vulns:[{package, installed_version, fixed_version?, ids, cves, severity, summary}], unfixed_count, notes[], error?}`. Inventaris kosong → `not_assessed`; rilis tidak didukung → `not_assessed` + alasan; feed gagal → `error` terisi dan **tidak pernah** daftar kosong yang terbaca sebagai "aman". `?unfixed=1` menyertakan temuan tanpa versi perbaikan. Ketika `vuln_intel_enabled` juga aktif, badge KEV/EPSS diambil lewat `vulnintel.Client.Lookup` pada CVE yang ditemukan dan diletakkan pada field `intel` dengan bentuk yang sama seperti `scanIntel`.
8. **UI.** Modul `static/app/osvvulns/` (bundel `/app/osvvulns.js` + `.css`, namespace `OV`, i18n EN/ID sendiri) menggambar kartu **Known vulnerabilities in installed packages** di bawah kartu Exploit intelligence pada tab Security: tabel paket/terpasang/diperbaiki/severity/CVE (sel CVE memakai `VI.findingCell` sehingga badge KEV/EPSS ikut tampil), filter teks, sakelar "include findings without a fix", keadaan mati yang menunjuk ke pengaturan, dan keadaan tidak dinilai. Pesan "tidak dinilai" pada kartu VI untuk apt/apk/pacman diubah agar menunjuk ke kartu baru ini alih-alih menyatakan tidak ada cakupan.

## Konsekuensi

- Host apt, apk, dan pacman akhirnya punya daftar CVE yang dapat ditindaklanjuti beserta versi perbaikannya, tanpa memasang apa pun di host.
- Admin harus mengaktifkan `osv_enabled` dan memahami bahwa nama paket, versi, dan rilis OS keluar dari server Pantau.
- Pemetaan sumber hanya akurat untuk dpkg dan apk; paket rpm tidak dicakup (OSV tidak punya ekosistem RHEL umum, dan [ADR 0064](0064-exploit-intelligence-kev-epss.md) sudah memberi CVE dnf/yum lewat advisory vendor).
- Untuk pacman, aturannya lebih konservatif daripada pacman sendiri: versi yang bentuknya berbeda dari versi `affected`/`fixed` tidak diklaim rentan, sehingga daftar bisa lebih pendek daripada `pacman -Si`.
- Rilis OS baru perlu ditambahkan ke daftar `debianMajors`/`ubuntuVers`/`alpineVers` di `internal/osv/ecosystem.go` sebelum cakupannya muncul; sampai itu host tersebut berstatus tidak dinilai.
- Kerentanan paket sumber tidak selalu berarti paket biner yang terpasang benar-benar mengandung kode rentan (versi build berbeda); Pantau menampilkan temuan paket sumber apa adanya.
