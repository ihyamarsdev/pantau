# 0062. Manajemen Firewall Host (ufw, firewalld, iptables) pada Tab Security

Melengkapi pemindaian keamanan pasif ([ADR 0036](0036-agentless-security-scan.md)) dengan kemampuan **membaca, menyiapkan, menambah, mengubah, dan menghapus** aturan firewall Host. Mengikuti pola aksi systemd ([ADR 0041](0041-systemd-service-actions-and-error-diagnosis.md)).

## Konteks dan Masalah

1. Hardening Check `firewall_active` hanya melaporkan apakah firewall aktif; memperbaikinya (memasang, mengaktifkan, membuka/menutup port) mengharuskan administrator membuka terminal.
2. Host Linux memakai salah satu dari tiga alat yang berbeda sintaks dan modelnya: ufw (aturan bernomor), firewalld (zona + service/port/rich rule, konfigurasi permanen vs runtime), iptables (rantai, kebijakan, tidak persisten).
3. Kesalahan firewall adalah salah satu penyebab paling umum hilangnya akses SSH ke server, dan Pantau sendiri mengakses Host lewat SSH.

## Keputusan Arsitektur

1. **Baca** (`GET /api/hosts/{id}/security/firewall`): satu perintah `sh -c` membaca ketiga alat (`ufw status verbose|numbered`, `firewall-cmd --permanent --list-all-zones`, `iptables -S`) dan mengembalikan `{supported, mode, ssh_port, backends[]}`; tiap backend memuat `installed`, `active`, `defaults`, `error` (keluaran alat bila aturan tak terbaca, biasanya tanpa root), dan `rules[]`. Hanya Linux; host lain `supported:false`. UI memuatnya **hanya saat tombol Load/Refresh ditekan**, bukan saat tab dibuka, agar tidak ada koneksi SSH dan probe sudo otomatis.
2. **Aksi** (`POST .../security/firewall/action` `{backend, action, rule?, old?}`): `setup`, `enable`, `disable`, `add`, `edit`, `delete`, `persist` (iptables). Hak akses seperti ADR 0041: root langsung, selain itu `sudo -n`, selain itu pengguna SSH apa adanya (mode `root`/`sudo`/`none` dikembalikan, dicatat ke Activity Console modul `firewall`, dan memperbarui backoff sudo yang sama). Semua langkah berjalan dalam satu subshell `set -e`.
3. **Keamanan masukan**: tidak ada teks bebas yang sampai ke shell tanpa validasi. Aksi, arah, protokol, port (1-65535 atau rentang `a:b`), alamat (IP/CIDR via `net`), antarmuka, zona, nama service, dan port firewalld divalidasi di Go; semua argumen di-quote dengan `shellQuote`. Rich rule firewalld hanya boleh satu baris yang diawali `rule ` dan dikirim sebagai satu argumen. Backend, kolom, atau aksi di luar daftar → HTTP 400.
4. **Perlindungan lock-out SSH**: aturan tanpa syarat (sumber mana pun, arah masuk) yang mengizinkan atau memblokir port SSH yang dipakai Pantau (`host.Port`, bukan 22 secara tetap) tidak dapat dihapus, diubah-keluar, atau ditambahkan sebagai blokir: HTTP 403 `ErrFirewallProtected`, dikerjakan lewat terminal. `enable` dan `setup` selalu mengizinkan port itu lebih dulu (ufw `allow N/tcp`, firewalld `--add-port`, iptables baseline `-I INPUT` di atas aturan lain sebelum kebijakan `DROP`). Aturan yang lebih sempit (sumber tertentu, port lain) tidak dilindungi karena tidak dapat memutus akses sendirian.
5. **Penjaga data basi**: `edit`/`delete` mengirim kembali `raw` aturan yang ditampilkan; skrip memeriksa bahwa nomor yang sama (ufw `status numbered`, iptables posisi dalam rantai) masih berisi teks yang sama sebelum mengubah, dan firewalld memeriksa `--query-*`. Bila berubah di host, skrip berhenti dengan exit 3 dan pesan "refresh the list" tanpa mengubah apa pun. ufw `edit` = guard → tambah (aturan v4 baru ditambahkan setelah semua aturan v4 sehingga nomor lama tetap) → hapus nomor lama; ditolak bila aturan baru identik dengan yang lama (ufw melewati aturan identik sehingga penghapusan akan menghilangkan satu-satunya salinan). iptables `edit` memakai `-R` (di tempat); pindah rantai ditolak. firewalld `edit` = query → add → remove → reload.
6. **Aturan read-only**: baris yang tidak dapat diregenerasi persis oleh formulir (iptables dengan `-m conntrack`/`multiport`/`comment`, `-j` ke chain lain, negasi; ufw dengan profil aplikasi, antarmuka, forward, atau baris `(v6)`) ditandai `editable:false`: tetap dapat dihapus tetapi tidak diubah, agar edit tidak diam-diam membuang opsi. Hanya rantai `INPUT`/`OUTPUT`/`FORWARD` iptables yang dikelola (rantai Docker/ufw tidak dicantumkan).
7. **Persistensi**: ufw dan firewalld (konfigurasi `--permanent` + `--reload`) persisten. Perubahan iptables hanya runtime; `persist` menyimpan lewat `netfilter-persistent save`, atau `iptables-save` ke `/etc/sysconfig/iptables` (RHEL), `/etc/iptables/iptables.rules` (Arch), atau `/etc/iptables/rules.v4`; bila tidak ada lokasi yang dikenali, hasilnya galat yang jujur dan aturan tetap hanya aktif di runtime.
8. **Setup**: memasang paket bila perintahnya belum ada (apt, dnf, yum, zypper, pacman, apk; non-interaktif), lalu baseline (butir 4): ufw = deny incoming / allow outgoing + SSH + enable; firewalld = `enable --now` + port SSH permanen; iptables = loopback + established + SSH, kebijakan `INPUT` `DROP`, lalu `persist`. Konfirmasi (dialog bahaya) selalu muncul untuk Setup, Disable, dan Delete.
9. **UI**: modul `static/app/firewall/` (bundel `/app/firewall.js`, namespace `Fw`, i18n EN/ID sendiri) menggambar kartu di bawah Port Exposure; `index.html` hanya menyisipkan kartu dan memanggil `Fw.render()`.

## Konsekuensi

- Firewall dapat disiapkan dan dikelola tanpa terminal; kesalahan umum (menutup port SSH, mengedit aturan yang sudah bergeser nomornya) ditolak oleh Pantau, bukan oleh host.
- Aksi membutuhkan root atau `sudo` tanpa kata sandi pada host; tanpa itu UI menampilkan peringatan dan galat asli alat.
- ufw dan firewalld yang aktif bersamaan dapat bentrok; UI memperingatkan tetapi tidak mencegahnya. Baris IPv4/IPv6 ufw adalah baris terpisah: menambah/mengubah membuat keduanya, baris `(v6)` lama dihapus sendiri.
- Di luar cakupan: `ip6tables`, ruleset native `nft`, tabel `nat`/`mangle`, kebijakan bawaan ufw selain lewat Setup, zona/antarmuka/source firewalld, dan reset total.
- Diverifikasi pada container Debian 12 nyata (ufw + iptables-nft, sshd, `NET_ADMIN`). firewalld tidak diuji pada daemon nyata (membutuhkan systemd + dbus); parsernya diuji terhadap fixture keluaran `firewall-cmd` dan skripnya hanya pada tingkat pembangunan perintah.
