# 0085. Supervisor VPN: circuit breaker per-Network, probe antarmuka aktif, dan telemetri

Optimisasi pada subsistem **VPN Networks** ([ADR 0077](0077-jalur-jaringan-per-host-driver-vpn-dan-dial-terikat-interface.md), [spesifikasi](../../.scratch/vpn-networks/spec.md)) setelah tiga insiden produksi: jalur yang tidak pernah naik karena konflik resolver, proses anak zombie yang mengunci supervisor, dan risiko banjir alert saat satu tunnel membawa banyak Host. Fokusnya adalah **reliabilitas, latensi rendah, dan observabilitas**: mendeteksi kegagalan jalur dalam milidetik, tidak membanjiri master dengan percobaan bring-up, dan membedakan "jalur mati" dari "Host mati" di UI maupun agen.

## Konteks dan Masalah

1. **Insiden NetBird DSI — resolver ditimpa, jalur tidak pernah naik.** Pada deployment DSI, Tailscale MagicDNS menulis ulang `/etc/resolv.conf` sehingga resolver NetBird hilang. `netbird up` gagal dengan `lookup net.digitalsekuriti.id: i/o timeout`; Network tidak pernah mencapai `up`, tetapi supervisor hanya melihat "proses masih ada" dan terus mencoba. Karena backoff saat itu tetap 30 detik tanpa *jitter* dan tanpa batas atas, satu Network yang gagal memicu **badai retry tiap 30 detik** yang tidak pernah konvergen — setiap siklus memakan slot inspeksi dan menulis galat yang sama. Akar masalahnya bukan proses mati, melainkan **kesehatan antarmuka/link** yang tidak pernah diperiksa secara aktif.
2. **Insiden zombie-child (addendum [ADR 0077](0077-jalur-jaringan-per-host-driver-vpn-dan-dial-terikat-interface.md)).** Daemon NetBird `mode: instance` mati tanpa pernah di-`Wait`, tetap tercatat "berjalan" sebagai zombie, `Down` menggantung selamanya sambil memegang kunci Network, dan setiap dial antre tanpa tenggat sampai slot inspeksi penuh — monitoring semua Host berhenti diam-diam. Status "proses hidup" terbukti bukan indikator yang cukup.
3. **Risiko banjir alert saat satu VPN membawa banyak Host.** Satu Network dapat menaungi puluhan Host ([spesifikasi](../../.scratch/vpn-networks/spec.md), [issue 09](../../.scratch/vpn-networks/issues/09-inspeksi-network-down.md)). Bila jalur putus dan setiap Host memicu alert "Host down" sendiri-sendiri, operator menerima puluhan notifikasi identik untuk **satu** kegagalan jalur. Inspeksi juga melakukan `Ensure` berulang per Host, memperparah badai retry dari poin 1.
4. **Telemetri yang tidak cukup untuk diagnosis.** `Status` hanya memuat `State`, `Iface`, `Detail`, `Err`, `Peers`, `CheckedAt`, `DNS` — tidak ada alamat virtual IP, latensi probe, atau keadaan *circuit breaker*. Operator dan agen ([ADR 0073](0073-in-process-ai-agent.md)) tidak bisa membedakan "sedang reconnect", "circuit open", atau "link probe gagal" tanpa membaca log mentah.
5. **Isolasi multi-instance yang rapuh.** Dua akun NetBird/tailnet tidak bisa berbagi daemon ([issue 11](../../.scratch/vpn-networks/issues/11-netbird-multi-instance.md)); bila state, socket, config, atau proses anak tumpang tindih, satu instance memutus instance lain — persis pola yang memperparah insiden DSI.

## Keputusan Arsitektur

1. **Probe antarmuka/link aktif, bukan pemeriksaan PID.** `vpnnet.Manager` mendapat `Probe(ctx, networkID) (Status, error)`: memeriksa antarmuka benar-benar ada (`net.InterfaceByName`), membawa alamat non-loopback, dan mengukur elapsed waktu probe dalam milidetik. `Status` diperluas dengan `VirtualIP string \`json:"virtual_ip"\`` (alamat pertama yang bisa dipakai, `""` bila tidak ada), `ProbeMs int64 \`json:"probe_ms"\`` (`-1` bila belum diukur), dan `Degraded bool \`json:"degraded"\`` (antarmuka ada tetapi probe link gagal). Field lama mempertahankan nama dan tag JSON-nya. `Probe` menyegar telemetri dan mengembalikan `Status`; ia dipakai baik oleh loop status maupun oleh endpoint/agen, sehingga "proses hidup" tidak lagi dianggap sehat.
2. **Backoff eksponensial dengan jitter dan batas.** Package var `backoffBase` (30 dtk), `backoffCap` (5 mnt), dan `backoffJitter` (fungsi `func() float64` menghasilkan pengali `[0.8, 1.2]`) dipakai helper `backoffDelay(fails int) time.Duration`. Delay tumbuh eksponensial dari basis 30 detik, dibatasi 5 menit, lalu dikali jitter agar banyak Network yang gagal bersamaan tidak sinkron lagi (menghilangkan badai retry 30 detik dari insiden DSI). Tes di package `vpnnet` boleh meng-override ketiga var tersebut untuk determinisme.
3. **Circuit breaker per-`network_id` di choke point `Ensure`.** `Ensure` fail-fast dengan `ErrNetworkDown` — pesan menyebut nama Network dan frasa "circuit open" — **sebelum** membaca DB atau memulai bring-up, bila breaker Network itu sedang `open`. Breaker opens saat transisi ke `down`/`error`, dan closes setelah cooldown (backoff) atau lebih awal bila `Probe` berhasil atau `Up` manual dipanggil. `BreakerState(networkID) string` mengembalikan `closed`, `open`, atau `half-open`. Karena `Ensure` adalah satu-satunya jalur ke dial ([choke point](../../.scratch/vpn-networks/spec.md), [issue 04](../../.scratch/vpn-networks/issues/04-supervisor-dan-gate.md)), satu pemeriksaan breaker di sana melindungi semua pemanggil (inspeksi, transfer, provisioner kunci) tanpa duplikasi logika.
4. **Isolasi state/konfigurasi/socket/proses yang ketat untuk instance NetBird/Tailscale.** Setiap Network `mode: instance` mendapat direktori `<root>` sendiri (config, state, socket `--daemon-addr`/`--socket`, log), `--interface-name` dan `--wireguard-port` unik, serta `--disable-dns` agar instance tidak saling menimpa resolver master ([issue 11](../../.scratch/vpn-networks/issues/11-netbird-multi-instance.md)). API menolak (400) dua `netbird/shared`, benturan iface/port, atau lewat batas proses anak. Ini langsung menutup celah yang dipakai insiden DSI untuk merusak resolver.
5. **Cache DNS yang diskop ke antarmuka, dengan TTL dan invalidasi.** Hasil resolusi melalui resolver jaringan (`Path.DNS`, mis. `dnsServers` NetBird atau `100.100.100.100` Tailscale) di-cache per antarmuka, bukan global, dengan TTL. Cache diinvalidasi saat alamat antarmuka berubah, saat Network turun/naik, dan saat konfigurasi disimpan — sehingga `lookup …: i/o timeout` tidak terulang karena resolver basi setelah MagicDNS menimpa `/etc/resolv.conf`. Jika tidak ada resolver jaringan, perilaku lama (resolver OS) tetap dipakai ([ADR 0077](0077-jalur-jaringan-per-host-driver-vpn-dan-dial-terikat-interface.md)).
6. **Pembatalan konteks yang bersih.** Semua goroutine supervisor — loop status, `Wait` proses anak, `stopChild`, pembaca log — dihentikan lewat `context.Context`, bukan flag global ([issue 04](../../.scratch/vpn-networks/issues/04-supervisor-dan-gate.md)). `Shutdown()` membatalkan konteks manajer, men-reap anak, dan melepas kunci Network; tidak ada lagi `Down` yang menggantung memegang kunci seperti insiden zombie. `Probe` dan `Ensure` menghormati konteks pemanggil sehingga slot inspeksi tidak pernah habis karena antrean tanpa tenggat.
7. **Pengelompokan Host `network_down` dan penekanan alert per-Host.** Host pada Network dengan `last_state != up` mendapat badge "Network down" (bukan "Host down" merah), dan KPI/filter mendapat kategori `network_down`. Inspector **tidak** mengeluarkan alert/notifikasi per-Host untuk kegagalan jalur ([issue 09](../../.scratch/vpn-networks/issues/09-inspeksi-network-down.md)); satu siklus inspeksi memanggil `Refresh`/`Ensure` sekali per Network, bukan sekali per Host. Warna dan badge mengikuti token semantik yang sudah ada ([ADR 0039](0039-modern-visual-design-system-and-icon-sprite.md)), jadi tidak ada literal warna baru.
8. **Telemetri yang diperkaya di seluruh permukaan.** Baris `GET /api/vpn/networks` menambah `virtual_ip` (string), `probe_ms` (int64), `degraded` (bool), dan `breaker` (string), semuanya bersumber dari `s.vpnMgr.Status(id)`; field lama tidak berubah dan rahasia tetap tersaring. Telemetri yang dimaksud mencakup alamat virtual IP, nama antarmuka, state driver, jumlah Host (`hosts_count`), latensi probe, galat yang sudah disanitasi, dan keadaan breaker. UI Settings → Networks menampilkan nilai-nilai ini pada tiap kartu beserta tombol **Probe** (`vpnNetworkProbe(id)`) dan **Reconnect** (`vpnNetworkUp(id)`), dengan kunci i18n baru `vpn_probe`, `vpn_reconnect`, `vpn_latency`, `vpn_virtual_ip`, `vpn_breaker_open`, `vpn_breaker_closed`, `vpn_breaker_half_open`, `vpn_degraded` dalam EN dan ID.
9. **API dan alat agen baru.** Endpoint `POST /api/vpn/networks/{id}/probe` mengembalikan `Status` dari probe aktif; bersifat **read-only** dan **tidak** memerlukan gate VPN (berbeda dengan `up`/`down` yang tetap bergate). Rute didaftarkan di `handleVPN`. Agen ([ADR 0073](0073-in-process-ai-agent.md)) mendapat `vpn_networks what: "telemetry"` dan alat baru `vpn_network_action` dengan `action: "probe"|"restart"` — `probe` read-only, `restart` memerlukan gate 1 / persetujuan operator — pada domain `network`.

## Konsekuensi dan Trade-off

- **Probe adalah pemeriksaan antarmuka lokal, bukan health check API vendor.** Ia menjawab "apakah tunnel bisa dipakai untuk dial sekarang?", bukan "apakah dashboard NetBird/Netmaker sehat?". Status vendor (`management.connected`, `BackendState`) tetap dilaporkan lewat `Detail`, tetapi tidak menentukan `up` sendirian — ini yang memperbaiki insiden DSI, sekaligus berarti degrade pada sisi vendor yang belum memutus antarmuka tidak selalu terdeteksi.
- **Breaker dapat menunda pemulihan hingga cooldown** bila dibiarkan sendiri. Operator atau agen bisa memaksa pemulihan lebih cepat lewat `Probe` yang berhasil atau `Up` manual; keduanya menutup breaker lebih awal. Jika keduanya tidak dipanggil, Network kembali dicoba setelah backoff maksimal 5 menit dengan jitter.
- **TTL cache DNS membatasi data basi**, tetapi juga berarti perubahan resolver vendor baru terlihat setelah TTL berakhir atau setelah invalidasi eksplisit (turun/naik/simpan konfigurasi). Ini disengaja agar tidak ada resolver lama yang dipakai terus seperti pada insiden DSI.
- **Rahasia tetap tidak pernah keluar dari API.** Telemetri baru hanya memuat alamat, state, latensi, dan galat tersaring; nilai `config` rahasia tetap write-only dengan penanda `*_set` ([ADR 0077](0077-jalur-jaringan-per-host-driver-vpn-dan-dial-terikat-interface.md)). Probe tidak menjalankan perintah dengan rahasia dan tidak memperluas permukaan baca rahasia.
- **Satu sumber kebenaran status** (`vpnMgr.Status`) dipakai API, UI, dan agen, sehingga angka yang ditampilkan konsisten; biayanya adalah `Status` kini harus menyimpan field telemetri tambahan di cache dan memperbaruinya pada setiap probe/refresh.
- **Jitter membuat waktu retry tidak deterministik** — tes harus meng-override `backoffJitter`; ini sudah diizinkan oleh kontrak package var.

## Alternatif yang Dipertimbangkan

1. **Liveness hanya berbasis PID** (status "proses masih ada" = sehat). Ditolak: justru penyebab insiden zombie-child dan insiden DSI — proses bisa hidup sementara antarmuka tidak membawa alamat atau resolver sudah rusak.
2. **Backoff tetap 30 detik tanpa jitter/batas atas.** Ditolak: sinkron antar-Network menghasilkan badai retry tiap 30 detik yang tidak konvergen; tanpa cap, delay tidak pernah stabil saat kegagalan berkepanjangan.
3. **Menekan alert per-Host hanya di UI.** Ditolak: notifikasi sudah dikirim di lapisan inspector sebelum UI menyaring, dan `Ensure` tetap dipanggil per Host. Penekanan harus terjadi di choke point (`Ensure`/breaker) dan di inspector (tanpa alert untuk `network_down`), dengan UI hanya menampilkan ringkasan.
4. **Polling API vendor sebagai health check.** Ditolak: tidak semua driver punya API/CLI status yang andal (Netmaker `peers = -1`, `custom` hanya exit code), menambah ketergantungan jaringan pada layanan eksternal, dan tidak menjawab apakah antarmuka lokal bisa dipakai untuk dial. Status vendor tetap dipakai sebagai `Detail`, bukan sebagai penentu `up`.

## Verifikasi

Parent akan menjalankan, sekali setelah semua slice selesai:

- `go test ./internal/vpnnet/... ./internal/sshrunner/... ./internal/inspector/... ./internal/store/...` — mencakup paket `internal/vpnnet` (probe, `backoffDelay`, breaker di `Ensure`, `Status` baru), `internal/sshrunner` (choke point `Target`/`ErrNetworkUnavailable`), `internal/inspector` (pengelompokan `network_down`, tanpa alert per-Host, satu `Ensure` per siklus), dan `internal/store` (kolom/telemetri Network). Tes package `vpnnet` meng-override `backoffBase`, `backoffCap`, dan `backoffJitter` untuk determinisme.
- `GOOS=windows go vet ./internal/vpnnet/...` dan `GOOS=darwin go vet ./internal/vpnnet/...` untuk bind per-OS ([spesifikasi](../../.scratch/vpn-networks/spec.md)).
- E2e: `cd e2e && npx e2e run tests/vpn-networks.e2e.ts` — mencakup CRUD Network, gate default mati menolak `up`, endpoint `probe` tanpa gate, kartu telemetri (virtual IP, `probe_ms`, badge degraded, breaker), tombol Probe/Reconnect, dan Host pada Network mati yang menampilkan "Network down" tanpa alert per-Host.
