# 0067. Repositori Git ter-clone (folder, edit, commit, push)

Menambahkan bagian **Repositories** (navigasi utama, mandiri dari Terraform dan Ansible): repositori Git di-clone penuh (SSH atau HTTPS) ke sebuah folder di server Pantau, lalu dijelajahi, diedit, di-commit, dan di-push dari dashboard. Melengkapi Git Editor stateless milik Workspace Terraform/Playbook Ansible (`internal/ansible/git_edit.go`, clone dangkal sementara per request) dan memakai ulang pola kredensial [ADR 0035](0035-ssh-key-library.md).

## Keputusan Arsitektur

1. **Clone persisten, bukan clone sementara**: satu folder per repositori di `Repositories Folder` (pengaturan `repos_dir`, bawaan `<data>/repos`). Perubahan folder hanya memengaruhi clone baru: path absolut tiap clone disimpan di `git_repos.dir`.
2. **Edit langsung ke working tree**: Save menulis file ke clone (tanpa commit). Commit & Push mem-stage path terpilih (kosong = semua), `commit --only` atas path itu, lalu `push -u origin HEAD:refs/heads/<branch>` ke branch aktif atau branch baru. Tanpa force push, merge, atau rebase; **Sync** = `fetch` branch aktif + `merge --ff-only`.
3. **Mesin di `internal/ansible/local_repo.go`** (paket yang sama dengan `git_edit.go` agar memakai ulang `setupGitEnv`, `validateSafeRelPath`, `checkNoSymlinks`, `sanitizeGitError`, dan `runCmd`). Kredensial tidak pernah disimpan di clone: token lewat `GIT_CONFIG_*` env, kunci SSH ditulis ke direktori sementara yang dihapus setelah tiap panggilan. Hook dimatikan (`core.hooksPath=/dev/null`), `GIT_LITERAL_PATHSPECS=1`, `GIT_ALLOW_PROTOCOL=https:ssh`, dan folder tanpa `.git` sendiri ditolak (git tidak boleh naik ke repo induk).
4. **Push yang gagal tidak membuang commit**: commit tetap lokal (status menampilkan ↑N), tombol **Push** mengulang setelah kredensial/remote diperbaiki. Token HTTPS atau kunci SSH wajib punya izin **tulis**; kredensial baca-saja menghasilkan 409 dengan pesan git yang disanitasi.
5. **Tabel `git_repos`** (`name` unik tanpa memedulikan huruf besar/kecil, `dir` unik, `auth` none/ssh/token, `token` write-only: API hanya mengembalikan `token_set`). **Tanpa gate opt-in**: berbeda dari Terraform/Ansible, tidak ada kode yang dieksekusi (hook git dimatikan), jadi cukup login admin. API di `/api/repos`. Menghapus entri menghapus folder clone (hanya folder bernama sama dengan repositori yang berisi `.git`).

6. **Clone sebagai job latar belakang**: `POST /api/repos` memvalidasi lalu mengembalikan `202 {job}`; `git clone --progress` berjalan di goroutine dengan stderr-nya ditangkap (pembaruan `\r` dilipat jadi satu baris, maks 300 baris, kredensial disamarkan) dan dibaca lewat `GET /api/repos/clone/{job}`; `DELETE` membatalkan dan folder parsial dihapus. Job hanya di memori (dibuang 10 menit setelah selesai); restart Pantau menghentikan clone yang berjalan.

7. **Pohon dimuat per folder, pencarian di server**: `GET /api/repos/{id}/tree?path=` memakai `git ls-tree` HEAD untuk satu folder (maks 2000 entri, simbol link dan submodule dilewati) dan browser menambahkan berkas/folder baru dari status; `GET /api/repos/{id}/search?q=` memakai `git ls-files` (tracked + untracked, tanpa yang di-ignore), semua kata harus cocok, nama berkas lebih dulu, maks 200. Daftar penuh satu kali (batas 2000) dibuang karena memotong repositori besar.
8. **Warna sintaks mengikuti nama berkas**: mode CodeMirror tambahan (`meta`, `simple`, `markdown`, `python`, `go`, `toml`, `properties`, `dockerfile`, `nginx`, `sql`, `diff`, versi 5.65.16 sama dengan inti) di-vendor ke `static/vendor/mode/` sesuai [ADR 0013](0013-airgapped-self-contained-web-assets.md); `.tf/.tfvars/.hcl` memakai mode HCL dari bundel Terraform (tanpa bundel itu tampil polos).

9. **Folder = grup sekaligus direktori**: kolom `git_repos.group_name` (kosong = langsung di lokasi). Clone dibuat di `<lokasi>/<folder>/<nama>`; UI mengelompokkan kartu per folder seperti Workspace Group (bagian dapat dilipat, jumlah repo, filter). `PUT /api/repos/{id}/group` memindahkan direktori (`rename`, satu lokasi/filesystem) dan memperbarui `dir`; folder yang kosong dihapus. Nama folder divalidasi seperti nama repositori, spelling folder yang sudah ada dipakai ulang tanpa memedulikan huruf besar/kecil, dan folder yang sendiri merupakan clone ditolak agar repositori tidak pernah dibuat di dalam repositori lain. Nama repositori tetap unik global (constraint `name` tidak diubah).

10. **Copy to host sebagai Transfer Job**: `POST /api/repos/{id}/copy` mengumpulkan berkas (ls-files tracked+untracked tanpa yang di-ignore, dikurangi yang dihapus; `.git` bila diminta), lalu `transfer.Manager.StartRepoCopy` mengalirkan arsip tar yang dibuat Go (`archive/tar`) lewat `io.Pipe` ke `tar -xf - -C <tujuan>` di host ([ADR 0003](0003-piped-streaming-cross-host-transfer.md); tanpa file sementara; job `kind: "repo"` di Transfer Queue). Symlink dan folder submodule **dilewati** (dihitung di `note`) karena tar yang diekstrak bisa menulis lewat symlink keluar dari tujuan. Tujuan harus absolut dan bukan Protected Path; sebelum data dikirim, `mkdir -p` + `test -w` memberi alasan yang terbaca (stderr tar tidak ditangkap oleh `PipeCommand`, jadi `2>&1` ditangkap dari stdout dan pesan host menang atas "broken pipe"). Tidak ada penghapusan berkas di host dan tidak ada mode terverifikasi.

## Konsekuensi

- Perubahan yang belum di-commit dan commit yang belum di-push hilang saat repositori dihapus; dialog konfirmasi menyebutkannya.
- Tidak ada adopsi folder git yang sudah ada dan tidak ada riwayat/diff commit; entri dan kredensial tidak ikut System Snapshot (clone dapat dibuat ulang dari URL).
- Satu mutex per folder menserialkan Sync/Commit/Push/Discard; clone dibatasi 5 menit per job.
- Host key SSH tidak diverifikasi (`StrictHostKeyChecking=no`), sama dengan Git Editor yang ada.
