# 0046. Kanal Notifikasi, Rule `http`/`tls`, Perintah Massal, Pembaruan Paket, dan Verifikasi Backup

Lima penambahan operasional dari daftar saran prioritas menengah. Rancangan: `.scratch/ops-monitoring/spec.md`. Semuanya agentless lewat SSH ([ADR 0001](0001-agentless-ssh-architecture.md)), tanpa dependensi baru (stdlib: `net/smtp`, `net/http`).

## Keputusan Arsitektur

1. **Kanal notifikasi tambahan**: ntfy, Slack, Discord (webhook masuk), dan SMTP (`starttls` bawaan | `tls` | `none`) di samping Telegram dan webhook generik. Pesan memakai sumber yang sama (Host, ringkasan, Root Cause Excerpt terpotong). `POST /api/settings/test-notify` mengirim ke semua kanal terkonfigurasi dan melaporkan hasil **per kanal** (`results[]`; `ok` tetap ada, kompatibel mundur). Rahasia baru (`ntfy_token`, `smtp_pass`) **tidak pernah dikembalikan** oleh `GET /api/settings`: hanya `ntfy_token_set`/`smtp_pass_set`; kunci tak dikirim = pertahankan, string kosong = hapus; dimasukkan ke Redaction Filter. Konsekuensi: respons `/api/settings` kini memuat nilai boolean selain string.
2. **Alert Debounce** (`alert_debounce_runs`, 1..10, bawaan 1): Drift baru memicu Incident, Alert, dan notifikasi hanya setelah terlihat pada N Inspection berturut-turut untuk rule yang sama; pulih langsung menutup (Alert Auto-Resolution tidak berubah). Penghitung in-memory per (Host, rule) dan hilang saat restart. Nilai di luar rentang dinormalisasi (bukan ditolak).
3. **Rule `http` dan `tls`** (Desired Rule Kind baru, tanpa migrasi): dijalankan **dari Host lewat SSH** (perspektif Host, seperti Network Egress), bukan dari server Pantau, supaya server tidak menjadi proksi SSRF. `http`: Target URL `http(s)://…` tanpa metakarakter shell, Expected `200|2xx|3xx|4xx` dan opsional `<Nms` (`curl -sS -o /dev/null -m 10 -w '%{http_code} %{time_total}'`, tanpa `-k`). `tls`: Target `host[:port]`, Expected `>=Nd` (bawaan 14), sisa hari dihitung dari `notAfter` (`openssl s_client` + `x509`); hanya masa berlaku, bukan validasi rantai. Alat tak tersedia atau handshake gagal → Drift dengan sebab (pesan curl/openssl masuk Root Cause Excerpt). Validasi Target/Expected saat menyimpan rule (400).
4. **Verifikasi isi backup**: `Expected = fresh_24h[,verify=gzip|tar|zstd|xz|sha256]` pada rule `backup`, dijalankan hanya bila berkas ada, tidak kosong, dan segar. `sha256` membandingkan dengan berkas sampingan `<berkas>.sha256` (tanpa itu: Drift "no checksum file"). Pola glob pada Target kini benar-benar terekspansi (sebelumnya `shellQuote` mencegahnya) dengan validasi pola yang ketat (mutlak, tanpa `..`, karakter terbatas) dan pemilihan berkas terbaru lewat `ls -t`. Rule lama tanpa `verify` berperilaku sama.
5. **Perintah massal** `POST /api/exec/bulk` (maks 20 Host, 4096 byte, timeout bawaan 30 dtk maks 120): respons NDJSON (satu baris per Host begitu selesai, konkurensi 5, keluaran dipotong 64 KB), non-interaktif, `sudo:true` hanya `sudo -n` (tidak pernah kata sandi). Konsisten dengan Kube Mode ([ADR 0044](0044-kubernetes-cluster-identity-usage-metrics-and-action-safety.md)): Host `no-exec`/`read-only` menolak perintah `kubectl … exec`. Dicatat ke Activity Console (modul `exec`), tanpa riwayat. UI meminta konfirmasi (jumlah Host + perintah). Batas jujur: perintah bebas dapat melakukan apa pun yang boleh dilakukan akun SSH; Kube Mode hanya pagar aplikasi.
6. **Pembaruan paket**: `GET …/packages/upgrade-preview` dan WebSocket `/ws/pkg/upgrade?mode=security|all` (biner, seperti log Docker). Mengikuti Docker Privilege Fallback (akun SSH biasa; `sudo -n` bila bukan root). Pratinjau memakai `sudo -n` untuk `dnf/yum` agar membaca metadata root (tanpa itu `dnf` non-root mencoba menyegarkan repo pihak ketiga dan gagal), melaporkan **paket unik** (bukan baris advisori) dan menampilkan galat dnf apa adanya (`ok:false`) alih-alih "0 pending". apt hanya `all` (tidak ada mode keamanan-saja yang andal); dnf/yum `all` atau `--security`. Perintah noninteraktif dibungkus `timeout 900`, satu proses per Host, penanda `[pantau] exit=N`, pindai ulang keamanan/paket di latar belakang sesudahnya. **Tidak ada reboot otomatis dan tidak ada rollback**; UI menyatakannya dan menyarankan Snapshot.
7. **Anggaran ukuran**: gzip `index.html` ±228 KB; batas pada `TestIndexGzipAndETagRevalidation` dinaikkan dari 220000 ke 240000.

## Konsekuensi

- Pesan `Test Notification` kini dapat mengirim ke beberapa kanal sekaligus; kanal gagal dilaporkan terpisah.
- Pemeriksaan `http`/`tls` menambah satu perintah SSH per rule per Inspection; di Host tanpa `curl`/`openssl` hasilnya Drift jelas, bukan galat tersembunyi.
- Perintah massal dan upgrade paket adalah mutasi pada Host produksi tanpa undo.
- Pengujian langsung menemukan dan memperbaiki empat cacat yang lolos dari unit test: (a) verifikasi backup selalu melapor "tool missing" karena kutip bersarang pada pembungkus `sh -c` (kini diuji dengan shell sungguhan), (b) pratinjau dnf melapor 0 pending ketika dnf gagal sebagai non-root, (c) hitungan keamanan/total adalah jumlah baris advisori (545/545 untuk 148/283 paket nyata), (d) label UI memakai kunci i18n yang belum didefinisikan (`timeout_sec`, `clear`, `copy`, `loading`, `actions`).
- Diverifikasi langsung (host AlmaLinux 10 nyata, penerima webhook dan SMTP lokal): perintah massal (validasi, sudo, timeout, pemotongan, Kube Mode), rule `http`/`tls`/`backup` termasuk verifikasi gzip/sha256 positif dan negatif, pemulihan menutup Alert, ketiga kanal HTTP dan SMTP, debounce (tak ada notifikasi pada Drift pertama, satu notifikasi pada kedua, tidak berulang pada ketiga), tidak ada kebocoran rahasia, UI di browser (pengaturan, form rule, dialog massal, pratinjau upgrade, dialog konfirmasi dibatalkan). **Eksekusi upgrade paket sungguhan dan aliran log WebSocket-nya tidak dijalankan** (hanya perakitan perintah, validasi input, dan pratinjau). Jalur apt, yum, dan macOS belum diuji pada Host nyata.
